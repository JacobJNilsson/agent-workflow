# CarbonCloud workspace

## Product specification and glossary

The cc-wiki repo in this workspace holds what the product
should do and the words we use for it. Treat it as a living reference in
every session, whichever repo you work in.

- Before you write text that stays, read cc-wiki/GLOSSARY.md
  and use its terms. This covers code comments, commit messages, PR
  descriptions, and specs. One word has one meaning.
- When review feedback settles a term, or corrects a word choice, add the
  term to GLOSSARY.md in the same session.
- When work uncovers product behaviour that no spec records, or proves a
  spec wrong, draft the spec update and show it to the user. Do not commit
  in cc-wiki without approval.
- Never mention cc-wiki in other repos. No links, paths, or
  mentions in code comments, commit messages, PR descriptions, or issues.
  State the reason for a behaviour in the PR text instead.
- Read cc-wiki/AGENTS.md before you write there. It sets the
  structure and the language rules.
